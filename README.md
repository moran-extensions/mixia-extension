# 秘匣 · 电脑验证码

> **秘匣鸿蒙版已上线华为应用商店，暂无 iOS 和安卓版本。**

文件导入版 **0.2.3**。秘匣已有的加密备份直接导入 Chrome，在电脑独立生成 TOTP 验证码。无需修改手机 App、安装连接助手、搭建服务器或配置网络。

[下载最新版本](https://github.com/moran-extensions/mixia-extension/releases/latest) · [问题反馈](https://github.com/moran-extensions/mixia-extension/issues) · [隐私说明](PRIVACY.md) · [Moran Extensions](https://github.com/moran-extensions)

## 使用

1. 手机秘匣打开 **设置 → 导出加密备份**，设置备份密码，保存 `.mixia` 文件。当前手机备份通常使用六位数字密码。
2. 用微信文件、数据线等方式把该加密文件保存到电脑。不要把备份密码和文件一起发送。
3. 下载并解压 Releases 中的扩展 ZIP，Chrome 打开 `chrome://extensions`，开启开发者模式，点击“加载已解压的扩展程序”，选择含 `manifest.json` 的解压目录。若下载的是源码，则选择其中的 `extension` 文件夹。普通安装无需 Node.js。更新时替换原目录文件并重新加载，不要先卸载，以免清除本机账户。
4. 首次打开插件，锁屏密码默认关闭，直接点击“开始导入”。在完整页面选择备份文件，输入**文件备份密码**，点击“解密并预览”。需要锁屏时，可主动开启开关并设置电脑密码。
5. 核对账户数量和预览，点击“确认导入并覆盖”。之后手机不在身边、电脑没有网络，也能生成验证码。
6. 手机新增、修改或删除账户后，重新导出文件并导入；每次确认后，电脑数据整体替换为文件中的数据。

导入操作在完整页面完成，避免选择文件时小弹窗关闭。点击右上角齿轮进入设置，其中的“导入备份”会自动打开该页面，同时支持手机和电脑导出的加密备份。弹窗主界面只保留紧凑工具栏、搜索和验证码列表，列表滚动时搜索框保持可见。

## 数据与限制

- 电脑只提供查看、搜索、复制及备份，不提供手动添加、编辑账户，不进行追加合并。
- 支持秘匣现有密码加密格式：PBKDF2-SHA256、AES-256-GCM、封装主密钥，含当前六位密码和旧版字符串密码。设备绑定/生物识别的内部库不能跨设备导入，请使用秘匣的“导出加密备份”。
- 仅支持 TOTP 时间验证码；若备份包含 HOTP 计次账户或不支持的类型，整份导入停止，不静默丢弃。SHA1/SHA256/SHA512、6–10 位和正整数周期均支持。
- 文件上限 10 MiB、账户数上限 2000、电脑规范化账户数据上限 6 MiB。密码错误、损坏、超限或保存失败时保留旧数据。
- 预览只留在内存中，两分钟有效；关闭、取消或锁定后不能再确认。空备份需额外勾选确认清空电脑账户。
- 电脑账户重新加密保存，不保存手机备份密码；不导入手机备注和分组，不使用 Chrome 云同步。
- 锁屏密码默认关闭：重新打开插件、浏览器重启或五分钟无操作后均可直接查看。关闭时，解密密钥保存在本机浏览器资料中，可使用该资料的人也可查看验证码。
- 在右上角设置中主动开启“锁屏密码”后，五分钟无操作、浏览器重启或后台被回收时需输入电脑密码；解锁后可随时关闭开关，账户不会丢失。
- 从 0.2.0 升级的已有保险库，需要先输入一次原电脑密码，转换完成后默认免解锁。
- 设置中的“导出备份”始终导出密码加密文件。锁屏开启时使用电脑密码；锁屏关闭时，在导出时单独设置至少 10 字符的备份密码，不会因此开启锁屏。恢复文件需要对应的导出密码，兼容旧版电脑备份。

插件无网络接口、网页脚本和主机访问权限。通过微信发送文件属于微信的传输行为，会经过所选工具的服务，不等于文件始终只在局域网内传输。手机六位数字备份密码强度有限，请妥善保管文件和密码；电脑独立密码不会提高已导出手机文件的密码强度。

## 构建和检查

无需生产或构建依赖，Node 运行版本建议 22 或以上：

```sh
npm run build
npm run check
npm test
npm run package
```

输出：

- `dist/mixia-extension-0.2.3.zip`：纯扩展包，`manifest.json` 位于 ZIP 根目录，可作为商店提交候选包或解压加载。
- `dist/mixia-extension-source-0.2.3.zip`：当前离线版源码与测试，不包含旧原型、助手、手机开发包或签名资料。

浏览器测试使用隔离的临时 Chrome 配置，在断网模拟下执行真实文件导入。安装 Puppeteer 后执行 `npm run test:browser`，也可以通过 `PUPPETEER_MODULE` 指定已有模块入口、`CHROME_EXECUTABLE` 指定 Chrome for Testing。

本机验证示例：

```sh
PUPPETEER_MODULE=/path/to/puppeteer/entry.js npm run test:browser
```

测试文件由原项目未改动的备份代码配合主机原生 API 适配器生成，全部为虚构账户，密码见 `tests/fixtures/README.md`。未读取真实保险库，也不需要提供真实备份给开发者。
